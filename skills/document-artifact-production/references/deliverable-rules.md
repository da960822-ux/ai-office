# Deliverable rules

## Universal

- Store every final artifact under `AI_OFFICE_OUTPUTS/<TASK-ID>/`.
- Keep department drafts under `departments/`; never present them as the final artifact.
- Include title, purpose, scope, assumptions, main content, evidence, risks, decisions, and next actions when applicable.
- Cite factual external claims with source URLs. Label unsupported figures as estimates.
- Record owner, artifact kind, status, path, and content hash.
- Completion requires an approved final artifact whose physical file exists.

## Market decision report

- Exactly one recommended business item.
- Include evaluated alternatives and explicit rejection reasons.
- Include customer/problem, evidence and sources, market/competition, business model, MVP, 90-day plan, unit economics/KPIs, risks, and recommendation rationale.

## Business plan or proposal

- Include executive summary, background/problem, goals, scope, stakeholders, approach, schedule, budget/resources, risks, KPIs, and approvals.

## Requirements or design specification

- Include context, goals/non-goals, users, requirements, acceptance criteria, dependencies, handoffs, risks, and validation plan.

## Meeting record

- Include date, participants, agenda, decisions, action owners, deadlines, unresolved issues, and evidence links.

## Format QA

- Markdown: UTF-8, valid headings, no placeholder text, working links.
- DOCX: render to images and inspect all pages for overflow, broken tables, clipping, and unreadable text.
- PDF: render pages and inspect; verify selectable text unless an image-only output was requested.
- Spreadsheet: validate formulas, error cells, data types, sheet names, and readable layout.
- Slides: render and inspect every slide; verify no overflow or clipped content.
- HWP/HWPX: use the available HWP workflow; if unavailable, create an approved alternate format and clearly report the limitation instead of claiming HWP completion.
