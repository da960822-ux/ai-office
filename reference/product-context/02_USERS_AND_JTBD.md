## 서비스가 받아야 하는 입력 수준

서비스는 아래 정도의 문장으로 작동해야 한다.

```text
취업 준비생이 면접 연습하고 분석받는 서비스를 만들고 싶어.
```

사용자에게 아래처럼 다시 쓰라고 요구하면 실패다.

```text
React, Spring Boot, MySQL 기반으로 JWT와 RAG를 적용한 서비스의
PRD, ERD, REST API 명세, EARS 요구사항을 작성해줘.
```

## 사용자가 몰라도 되는 것

- PRD 형식
- 사용자 스토리 문법
- REST API 명명
- DB 정규화
- 컴포넌트 계층
- 모델 라우팅
- 에이전트 역할 분배
- 컨텍스트 파일 규칙

## 사용자가 결정해야 하는 것

- 누구를 위한 제품인가
- 가장 중요한 결과는 무엇인가
- 발표에서 보여줄 핵심 행동은 무엇인가
- 일정과 팀 규모는 어느 정도인가
- 반드시 포함할 기능은 무엇인가
- 추천 방향을 승인할 것인가

## 불안과 대응

| 사용자 불안 | 제품 대응 |
|---|---|
| 무엇을 입력할지 모르겠다 | 시작 카드, 예시, 짧은 입력 |
| 잘못 선택할까 걱정된다 | 추천 배지, 이유, 변경 가능 여부 |
| 기능이 너무 많다 | MVP/Later 자동 분리 |
| AI가 멋대로 바꾼다 | 승인, diff, 결정 로그 |
| 결과가 깨질까 걱정된다 | 체크포인트와 롤백 |
| 오류를 모르겠다 | 쉬운 설명 + 기술 세부 |
| 다른 AI로 옮기기 어렵다 | Codex·Claude 인계 패키지 |
