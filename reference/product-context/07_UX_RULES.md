# 07. UX Rules for Non-Technical Builders

## 핵심 목표

사용자가 `AI에게 정확히 명령하는 법`을 배우지 않아도 된다. 제품이 불완전한 생각을 이해 가능한 선택과 결과로 바꾼다.

## 1. 빈 채팅창 금지

첫 화면에 다음을 제공한다.

- 프로젝트 시작 유형
- 실제 예시
- 최근 프로젝트
- 추천대로 빠르게 시작
- 파일·저장소 가져오기

채팅은 입력 방식 중 하나일 뿐 전체 UI가 아니다.

## 2. 한 번에 한 결정

좋은 순서:

```text
누구를 위한 것인가
→ 가장 중요한 행동
→ 일정
→ 추천 범위 확인
```

기획·DB·인증·배포·디자인·API를 한 화면에서 모두 묻지 않는다.

## 3. 추천 기본값

```text
추천: 로그인 없이 데모 먼저 만들기
이유: 3주 프로젝트에서 핵심 분석 흐름을 먼저 검증할 수 있습니다.
나중에 변경: 가능
```

`자동`이라고만 쓰지 말고 결과와 이유를 설명한다.

## 4. 점진적 공개

기본:

- 핵심 결정
- 시안
- 다음 작업
- 문제점

펼치기:

- 기술 세부
- 에이전트 기록
- 모델
- 비용
- JSON
- 원본 오류

## 5. 전문 용어 번역

| 기술 용어 | 기본 표시 |
|---|---|
| Authentication | 사용자 구분이 필요한가요? |
| Persistence | 다시 들어와도 데이터를 남겨야 하나요? |
| API Contract | 화면과 서버가 주고받는 데이터 |
| Schema Validation | AI 결과 형식 확인 |
| Rollback | 이전 정상 상태로 돌아가기 |
| Dependency | 먼저 끝나야 하는 작업 |
| Acceptance Criteria | 끝났다고 판단하는 기준 |

## 6. 세 가지 수정 방식

1. 카드 선택
2. 화면 직접 편집
3. 자연어 요청

예:

- 기능을 더 작게
- 발표 임팩트를 높여줘
- 이 화면만 밝게
- 로그인은 나중으로 미뤄
- 이 버튼이 왜 필요한지 설명해줘

## 7. 변경 영향 표시

```text
로그인을 제거하면:
- 온보딩 화면 2개가 삭제됩니다.
- 사용자별 저장은 데모 데이터로 바뀝니다.
- 백엔드 작업 4개가 줄어듭니다.
```

## 8. 진행 상태

퍼센트만 표시하지 않는다.

```text
현재: 핵심 화면 4개 생성
다음: 화면과 요구사항 맞추기
대기: 사용자 시안 승인
```

## 9. 오류 UX

```text
시안은 생성됐지만 화면 이동 규칙을 만들지 못했습니다.
현재 결과는 볼 수 있습니다. 이동 규칙만 다시 생성하면 됩니다.
[자동 재시도] [현재 결과 유지] [기술 내용 보기]
```

기술 세부에는 error code, failed step, retry count, provider message, trace ID를 둔다.

## 10. 신뢰 UX

- 추정값 표시
- 자동 변경 전 diff
- 위험 작업 승인
- 체크포인트
- 산출물 버전
- 테스트 증거
- 실패 항목 숨기지 않기

## 11. 오피스 UI

권장 구조:

- 중앙: 시안 또는 산출물
- 좌측: 단계와 작업
- 우측: 결정·검토·도움말
- 별도 탭: 오피스 시각화

아바타를 클릭해야만 작업 내용을 찾는 구조는 피한다. 모바일에서는 산출물 확인과 승인을 애니메이션보다 우선한다.

## 12. 접근성

- 색상만으로 상태 구분하지 않음
- 키보드로 주요 흐름 가능
- 명확한 focus
- 오류를 입력 근처에 표시
- 긴 표는 모바일 카드로 변환
