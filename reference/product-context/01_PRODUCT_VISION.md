# 01. Product Vision

## 제품 카테고리

- 권장: **Guided Product-to-Code Workspace**
- 보조: AI Product Pre-Builder
- 한국어: 초보자를 위한 AI 제품 설계·시안·개발 인계 공간

`AI 소프트웨어 회사`는 내부 경험과 시각적 메타포로 유지하되 외부 핵심 포지셔닝으로는 쓰지 않는다. 너무 크고 실제 사용자 가치가 모호하기 때문이다.

## 권장 포지셔닝

> 복잡하게 명령하지 않아도, 아이디어를 기본 수준의 제품 시안과 개발 가능한 산출물로 바꿔주는 AI 제품팀.

> 만들고 싶은 것을 짧게 말하면 필요한 질문만 골라 묻고, 현실적인 MVP를 정한 뒤 화면 시안·요구사항·작업 목록을 만든다. 결과는 Codex나 Claude Code에서 그대로 이어서 구현할 수 있다.

## 태그라인 후보

1. 아이디어만 말하세요. 만들 수 있는 형태로 정리해드립니다.
2. 프롬프트보다 제품에 집중하세요.
3. 막연한 아이디어에서 실행 가능한 첫 버전까지.
4. 코딩 에이전트가 일하기 좋은 프로젝트를 먼저 만듭니다.

## 차별점

일반 앱 빌더는 코드를 빠르게 만든다.  
일반 PM 도구는 문서와 로드맵을 만든다.  
일반 멀티에이전트 도구는 에이전트 실행을 관리한다.

VibeOffice는 그 사이를 연결한다.

```text
쉬운 의도 입력
+ 제품 범위 결정
+ 빠른 기본 시안
+ 구조화된 개발 산출물
+ 도구 중립적 인계
```

## 초기 시장 진입점

> 1~4명의 비전공 부트캠프 팀이 1~4주 안에 발표 가능한 웹·AI 서비스 데모를 만드는 상황

이 상황은 기간, 팀, 기술 수준, 발표 우선순위가 명확해 범위 추천이 가능하다.

## 초기 지원 유형

1. 랜딩 페이지 + 핵심 데모
2. CRUD 웹 서비스
3. 대시보드·관리 도구
4. 외부 AI API를 활용한 데모
5. 포트폴리오·프로젝트 소개 사이트

초기 제외: 대규모 커머스, 금융·의료, 복잡한 네이티브 앱, 실시간 대규모 협업, 프로덕션 결제.

## 기초 완성의 정의

- 제품 목적과 대상이 한 문장으로 설명된다.
- MVP와 제외 기능이 구분된다.
- 핵심 흐름이 끊기지 않는다.
- 주요 화면과 상태가 존재한다.
- 버튼은 동작하거나 비활성 이유가 있다.
- 데이터 계약 또는 명시적 mock이 있다.
- 작업 목록과 수용 기준이 있다.
- Codex가 추가 핵심 질문 없이 첫 작업을 시작할 수 있다.
- 공식 빌드 또는 기본 검증이 통과한다.

상용 운영 수준의 보안·확장성·결제까지 의미하지 않는다.

## North Star

**Idea-to-Validated-First-Draft Rate**

첫 아이디어 이후 아래 네 가지를 모두 확보한 비율:

1. 승인된 MVP 범위
2. 확인 가능한 UI 시안
3. 구조화된 개발 작업
4. 내보내기 가능한 인계 패키지
