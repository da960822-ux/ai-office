# 09. Acceptance Criteria

## 시작

- 첫 방문에 빈 채팅창만 보이지 않고 4개 이상의 시작 유형과 예시가 보인다.
- 한 문장 아이디어만으로 추정 블루프린트를 만든다.
- Quick Draft의 필수 질문은 최대 3개를 목표로 하고 추천값 진행을 제공한다.
- 이미 입력한 정보를 반복 질문하지 않는다.

## 블루프린트

- 대상 사용자, 문제, 성공 장면, MVP, 제외 기능, 위험이 존재한다.
- 각 필드가 확정/추천/미정 상태를 가진다.
- 기능 변경 시 영향받는 산출물이 표시된다.

## 범위

- 기간·팀·숙련도에 비해 과도하면 Must/Later로 나누고 이유를 설명한다.
- 핵심 가치와 연결되지 않은 기능은 자동 P0가 되지 않는다.
- Out 기능은 TASKS.md에 없다.

## 시안

- 핵심 화면 3~7개가 생성된다.
- 주요 CTA는 실제 이동·상태 변경·명시적 disabled 중 하나다.
- 데이터 화면에 loading/empty/error가 있다.
- 코드 프리뷰가 있으면 공식 build가 통과한다.

## 산출물

- PRD, Tasks, AGENTS.md는 필수다. Product Brief·Requirements는 외부 인계나 대형 프로젝트에서만 PRD에서 파생한다.
- 프로젝트명과 기능명이 파일 간 일치한다.
- 각 Must 요구사항은 화면과 작업에 연결된다.
- Markdown과 JSON으로 내려받을 수 있다.

## 검토

- 심각도, 문제, 영향, 수정안, 관련 산출물이 있다.
- Blocker가 남으면 내보내기 전에 경고한다.
- 경고 무시는 Decision Log에 남는다.

## 실패·복구

- 모델 호출 하나가 실패해도 이전 산출물이 사라지지 않는다.
- 마지막 승인 체크포인트로 복구할 수 있다.
- 오류에 쉬운 설명, 영향, 재시도, 기술 상세가 있다.

## 내보내기

- Codex 패키지에 AGENTS.md와 NEXT_ACTION.md가 있다.
- Claude 패키지에 CLAUDE.md 또는 범용 인계가 있다.
- 비밀키, 토큰, 로컬 절대경로가 없다.
- 패키지만 읽어도 첫 작업의 목표·범위·검증 명령을 알 수 있다.

## 기존 코드

- 저장소 연결 시 구조와 실행 방법을 먼저 조사한다.
- 변경 계획은 유지/수정/추가/제거를 구분한다.
- 사용자 변경을 승인 없이 덮어쓰지 않는다.

## 오피스 UI

- 오피스 없이도 모든 핵심 기능에 접근 가능하다.
- 내부 사고 대신 단계, 결과, 차단 이유를 보여준다.
- 모바일에서 산출물과 승인이 아바타보다 우선한다.

## MVP 출시 기준선

- 대표 시나리오 3개 E2E 성공
- 블루프린트 필수 스키마 검증
- ZIP 내보내기 성공
- 체크포인트 복구 성공
- 치명적인 화면 dead-end 없음
- Blocker 0개
- 초보 사용자 5명 중 4명 이상이 별도 프롬프트 교육 없이 첫 패키지 생성
