# Codex용 프로젝트 컨텍스트

## 한 문장 정의

**VibeOffice는 비전공 부트캠프 참여자의 거친 아이디어를 현실적인 MVP, 기본 UI 시안, 개발 명세, 실행 작업으로 변환해 Codex·Claude Code에 넘기는 Guided Product-to-Code Workspace다.**

## 해결 문제

초보 사용자는 AI 코딩 도구의 성능보다 다음에서 더 자주 막힌다.

- 무엇부터 설명해야 할지 모른다.
- 기능을 너무 크게 잡는다.
- 긴 프롬프트를 써야 한다고 느낀다.
- 화면·API·DB·작업이 서로 맞지 않는다.
- 오류가 나면 무엇을 수정해야 할지 모른다.
- 대화가 길어지며 초기 결정이 사라진다.
- 다른 AI 도구로 옮길 때 설명을 반복한다.
- 예쁜 결과가 실제로 작동하는지 판단하기 어렵다.

## 약속하는 결과

사용자는 한두 문장과 몇 번의 선택으로 다음을 얻는다.

1. 제품 요약과 목표 사용자
2. MVP 포함·제외 범위
3. 핵심 사용자 흐름
4. 화면 목록과 기본 시안
5. 기능 요구사항과 수용 기준
6. 기술 방향·데이터·API 초안
7. 실행 작업 목록
8. 검토 결과와 위험
9. Codex·Claude Code 인계 파일
10. 선택한 템플릿에서는 실행 가능한 기본 골격

## 제품 위치

```text
아이디어
  ↓
VibeOffice
- 질문 최소화
- 범위 통제
- 기획·UX·기술 정렬
- 시안·산출물·작업 생성
- 검토·버전·복구
  ↓
Codex / Claude Code / Cursor
- 세부 구현
- 리팩터링
- 테스트
- 배포
```

## 하지 않을 약속

- 한 문장으로 모든 종류의 상용 서비스 완성
- 사람 검토 없는 완전 자율 개발
- 모든 기술 스택 동시 지원
- 에이전트 수가 많을수록 좋다는 주장
- 멋진 AI 회의 장면 자체를 핵심 가치로 판매
- 보안·결제·개인정보 기능의 무검증 자동 생성

## 초기 핵심 사용자

- 비전공 개발 부트캠프 참여자
- 1~4명, 1~4주 단기 팀 프로젝트
- 처음 PM 역할을 맡은 팀원
- Codex·Claude Code 지시가 어려운 사용자
- 발표 가능한 포트폴리오 데모를 만들려는 취업 준비자

## 성공 상태

```text
시작 전: “뭘 어떻게 말해야 하지?”
시작 후: “이 범위라면 만들 수 있고 다음 작업이 뭔지 알겠다.”
```

새 기능은 다음 중 셋 이상을 만족해야 P0 후보가 된다.

1. 사용자가 더 적게 설명해도 되는가
2. 결과물이 더 일관되고 실행 가능해지는가
3. 다음 행동을 쉽게 고를 수 있는가
4. 실패 후 복구가 쉬워지는가
5. 다른 코딩 에이전트로 넘기기 쉬워지는가
