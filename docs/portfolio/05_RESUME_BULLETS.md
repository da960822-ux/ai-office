# 이력서 불릿: AI Office (Corporate OS v6.2)

X-Y-Z 포뮬라(달성 [X] as measured by [Y] by doing [Z]) 기준으로 작성. 숫자는 전부 저장소에서 직접 측정한 값(`git log`, `wc -l`)이며, 매출·사용자 수 같은 외부 비즈니스 지표는 개인 프로젝트 특성상 존재하지 않아 넣지 않았다.

## 아키텍처 / 시스템 설계

- 24명 AI 에이전트·8개 부서 조직을 모델링하는 멀티 에이전트 실행 시스템을 9일간(커밋 49건) 단독 설계·구현. Task/Job 상태 분리, SQLite WAL 기반 lease·heartbeat로 워커 장애 시 자동 복구 구조를 갖춤
- "완료 판정" 로직을 파일 hash·검증 명령 종료 코드·독립 리뷰 통과 3중 조건으로 설계해, 모델 자기 보고만으로 작업이 완료 처리되는 신뢰 문제를 아키텍처 레벨에서 차단
- TaskContract 기반 3단계 권한 모델(allow/ask/deny)을 설계해, 에이전트별 파일 접근·명령 실행 범위를 요청 단위로 제한하고 위험 등급은 HTTP 428로 승인 대기하도록 구현

## 품질 · 신뢰성 엔지니어링

- 정적 정합성 검사 스크립트 3종(`verify_routing.py`, `verify_skills.py`, `audit_package.py`)을 자체 구축해 24명·8부서 조직의 설정 누락, 스킬 lock 불일치, YAML 파싱 오류를 배포 전에 기계적으로 검출
- Windows/macOS/Linux 크로스플랫폼 스킬 검증 시스템에서 서브디렉토리 스킬 102개 중 98개가 해시 불일치로 실패하던 문제를, 경로 직렬화(`.as_posix()`) 및 `.gitattributes` 줄바꿈 고정 두 가지 근본 원인으로 분리 진단해 해결
- 부서 파이프라인 게이트가 fallback plan 경로에서 우회 가능하던 보안 허점을 발견·수정하고 회귀 테스트 72줄 추가, E2E 테스트 절반을 무력화하던 bare `return` 및 도달 불가능한 API 엔드포인트를 제거
- 9일 개발 기간 동안 조용한 실패(silent failure) 유형 버그 6건을 자체 발견·수정하고 각 사례를 트러블슈팅 문서로 기록해 재발 방지 체크리스트화

## PM 관점 의사결정

- 멀티테넌트·자동 배포·무제한 자율 실행을 비목표로 README에 명시해 9일 스코프 내에서 핵심 신뢰 문제(증거 기반 완료 판정)에 집중, 스코프 크리프 없이 완주
- 정적 라우팅과 동적 라우팅의 트레이드오프를 24명·8부서 규모의 유지보수 비용 기준으로 분석해 동적 라우팅을 채택하고, `verify_routing.py`로 예측 불가능성을 상쇄하는 보완 장치를 설계

## 자기소개서/면접용 한 줄 요약
